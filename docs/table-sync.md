# 名单同步到飞书多维表

“名单同步”仅系统所有者和管理员可用。来源为系统已同步的通讯录数据库，不读取旧脚本的两张来源多维表，不改变积分、通知、撤回和通讯录同步逻辑。

## 首次上线

1. 在目标数据库执行 `database/schema.sql` 第九段“独立名单同步任务”，创建三张新表。该段可以重复执行，不修改既有业务表；应用启动不会自动升级表结构。
2. 给积分系统当前飞书应用开通目标表记录读取、创建、更新、删除和字段/数据表读取权限，发布生效；将应用添加为目标多维表的可编辑协作者。Wiki 链接还需读取对应知识库节点的权限。网页能打开表格不代表应用有权读写。
3. 按原有部署命令重新构建并启动服务。新增 `table-sync` 容器复用后端镜像，独立运行，不向现有通知 worker 添加任务。
4. 接管旧脚本的目标表前停止旧定时任务，避免两套程序同时维护同一张数据表。先预览、手动执行并核验，再开启新任务定时。

## 配置任务

进入“名单同步”新建任务，选择“公共名单”或“任务专属名单”。公共名单每次读取最新规则；专属名单在任务内选择部门和人员，不显示到公共/个人发送名单页面。

粘贴飞书多维表链接（`https://企业.feishu.cn/base/…?table=tbl…` 或知识库 `/wiki/…` 链接），点击读取目标表。没有指定数据表时先选择数据表，再读取字段。只会维护选择的数据表，不使用链接中的视图筛选条件。

将来源的“部门、姓名、user_id”分别映射到三个不同的可写文本字段。通常可直接匹配同名字段；“序号”等自动编号和其他列不写入。同一个目标数据表只能由一个任务维护。

“部门”为所有有效所属部门的末级名称去重、排序后用“；”合并；无部门归属时为“直属企业”。人员按系统现有名单规则筛选，`user_id` 为同步唯一键。缺少 `user_id`、失效部门、待确认人员状态等异常会阻止执行并显示原因。

任务先保存，再点击“预览同步差异”查看计划新增、修改、删除、重复和不变的明细。预览只读。点击“执行一次”会在后台排队执行，离开页面不影响执行。

## 定时与关闭

Cron 使用标准五字段 `分 时 日 月 星期`，固定北京时间。页面可检查未来执行时间，例如：

| 表达式 | 含义 |
|---|---|
| `0 4 * * *` | 每天 04:00 |
| `0 9 * * 1-5` | 周一至周五 09:00 |
| `0 */6 * * *` | 每六小时的整点 |

新任务默认关闭。保存配置或切换开关后后台自动生效，不需要修改环境变量或重启容器。关闭只停止后续定时触发，已受理执行继续完成；关闭时仍允许单次手动执行，手动执行不会改变 Cron 计划。同一任务不重叠排队/运行，到点已有执行会记录跳过；停机错过多个时刻恢复后合并执行一次。

## 同步结果及恢复

每次读取目标表完整数据后按 `user_id` 增量对齐。先增改，全部确认后再清理名单外、空 ID 和重复记录，最后核验最终内容。已有记录的 ID、自动编号及未映射列保留。源数据与目标一致时不写入，记录“无变化”。正常、有效且完整解析为零人的名单会清空目标数据表。

超时或不完整响应可能表示部分记录已写入，本次停止后续删除并记录失败。下一次执行重新读取实际目标状态计算差异，不盲目重放上次新增。执行中来源变化也会停止后续写入，重新执行即可。

每个任务及“全部执行记录”提供状态/种类筛选、差异明细和阶段日志，包括触发方式、起止时间、数量及安全错误原因。记录默认保存 90 天，后台小批清理。删除任务仅软删除配置并释放目标占用，历史在保留期内仍可查看。

## 运维

独立服务单实例、并发一项任务、请求默认每秒最多一次，每批最多 200 条；使用小连接池、256 MiB 内存和 0.5 CPU 上限。不要横向扩容本服务；数据库会话锁阻止重复启动。单次执行超过 15 分钟会先终止子进程再标记中断，服务重启后不会盲目重放旧写入。

异常断连后若仍有旧运行记录，接管服务先等待旧租约结束及 90 秒请求收尾时间，再回收中断状态。等待期间健康检查保持更新，防止旧在途请求尚未结束就启动下一次写入。

查看服务：`docker compose ps table-sync`；查看运行日志：`docker compose logs --tail=100 table-sync`。停止新增同步功能可执行 `docker compose stop table-sync`，不需要停止 API、前端或原通知 worker。停止服务期间的手动请求会保持排队，服务恢复后处理。

本地开发仍可使用原启动脚本运行现有业务；需要执行新模块任务时，在另一个终端进入 `backend`，用项目虚拟环境运行 `python -m app.table_sync.worker`。该独立进程使用相同环境配置和数据库，启动前需已执行第九段增量。
