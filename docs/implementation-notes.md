# 实现与验收记录

## 已实现

单人 / 多人共用分值和原因；逐人月度总分与手动覆盖；独立通知范围；部门路径交集、全范围勾选和额外人员；私有动态发送配置；预览有效期及内容变化校验；幂等记账；持久化后台队列；消息 ID 保存；失败重试；飞书 OAuth 登录、CSRF、角色管理和最后管理员保护；人员全量同步及 SDK 长连接事件处理；24 小时内整批及单条消息撤回、独立任务记录、失败重试和租约恢复。名称统一为 `ORVIBO_员工积分系统`，提供页面 Logo 和 favicon；员工头像统一读取 `avatar_url`，空地址或加载失败显示人员占位图标。

积分账本不依赖飞书多维表格或 AnyCross。MySQL 8 结构仅由 `database/schema.sql` 维护，变更按日期追加在末尾，管理员手动执行；本地启动和 Docker Compose 均不修改数据库结构。事务和通知网络调用分离；通知发送重试不能更改月度余额。

撤回按每笔记分判断：全部通知成功撤回才作废积分，部分撤回、未发送、失败或待核实仍保留积分。作废审计、余额重算及最后一条撤回成功状态在同一事务内保存，与记账共用写锁；唯一流水主键防止重复作废。重算该月有效流水时按原余额版本排序，避免同秒时间戳打乱手动覆盖的先后顺序。月度余额版本递增使旧预览失效，即使后续覆盖导致总分不变也需要重新预览。原流水、卡片和消息 ID 均保留；worker 补处理历史全部撤回的记分。

## 本地验收

- Vue TypeScript 检查和包含自托管字体的 Vite 生产构建通过。
- 未登录时打开首页直接跳转到飞书官方授权页，浏览器已核对应用名称及授权按钮；已有会话进入系统，取消授权后停留在重试提示，防止自动跳转循环。
- 本地启动脚本的 7 项测试通过，包含配置端口、API 启动顺序、进程退出清理，以及启动不执行数据库更新。
- 隔离 MySQL 8 实例上的 88 项测试通过，覆盖记账和通知的既有场景，并新增全部通知成功才作废、未发送和失败阻止作废、多员工独立处理、手动覆盖及零总分重算、同秒提交顺序、跨月撤回、旧预览失效、事务回滚、最后两条通知并发成功只作废一次、历史全部撤回补处理和重复确认不恢复积分。
- 使用 MySQL 原生命令行执行 DDL，验证空库初始化、已有库增量和重复执行；增量在原表使用 utf8mb4_unicode_ci、utf8mb4_0900_ai_ci 或不同字段字符集 / 排序规则时均能建立外键。撤回表 12 个字段均含中文注释，员工、user_id、头像、权限和余额保留。
- 浏览器完成多人加分、个人配置保存、逐人覆盖、预览切换、发送前确认及后台模拟投递。张三覆盖为 85 分、李四自动 65 分，生成两条独立模拟消息；后续张三加 3 分显示 88 分。
- 刷新并重新登录后，已保存的个人配置可重新选择，通知名单正确恢复。
- 390 像素手机布局为单列，1280 像素桌面布局为双栏，两者均无横向溢出；视觉核对暖米底、赤陶橙、绿红语义色。
- 已从飞书卡片搭建工具核对线上版本与源码：加分 `AAqzjRLLF2LbI` / `1.0.4`，扣分 `AAqzj4Y1vmkf7` / `1.0.3`；五个变量均为文本，加分模板自带正号，扣分直接显示带负号的 score。模板和变量固定在代码中，无需环境变量。
- 浏览器检查新的绿色加分和橙色扣分预览，覆盖完整部门路径、多部门、换行原因、负总分和零总分；桌面与手机无横向溢出。正式预览直接读取发送快照中的变量。
- 撤回表使用独立增量 SQL，外键字段匹配已有表的类型、字符集及排序规则，保留员工、权限、余额及投递记录。
- 作废审计表的 6 个字段及表名均有中文注释；MySQL 原生 CLI 验证空库初始化、增量重复执行，以及员工 ID 使用 ASCII、流水 ID 使用 utf8mb4_0900_ai_ci 时的外键兼容。
- 浏览器隔离演示完成单条撤回、整批跳过已撤回消息、结果自动刷新、超时入口隐藏；模拟消息 ID 保留。真实员工头像地址可加载，空地址和失效地址使用统一占位图标；正式预览和确认弹窗使用同一员工头像。390 像素手机尺寸下人员列表、头像、撤回结果弹窗和权限页均无横向溢出。
- 本轮浏览器使用独立模拟 API，验证张三只撤回一条仍为 65 分、全部撤回后为 60 分且李四仍为 85 分；随后整批撤回李四通知，独立作废为 60 分。历史显示作废数量，原发送总分保留，操作台自动更新为 60 → 65，旧预览清除；桌面及 390 像素手机结果弹窗无横向溢出。本轮没有调用真实飞书发送或撤回，也没有执行正式数据库增量。
