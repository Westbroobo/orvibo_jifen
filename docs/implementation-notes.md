# 实现与验收记录

## 已实现

单人 / 多人共用分值和原因；逐人月度总分与手动覆盖；独立通知范围；部门路径交集、全范围勾选和额外人员；私有动态发送配置；预览有效期及内容变化校验；幂等记账；持久化后台队列；消息 ID 保存；失败重试；飞书 OAuth 登录、CSRF、角色管理和最后管理员保护；人员全量同步及 SDK 长连接事件处理；24 小时内整批及单条消息撤回、独立任务记录、失败重试和租约恢复。名称统一为 `ORVIBO_员工积分系统`，提供页面 Logo 和 favicon；员工头像统一读取 `avatar_url`，空地址或加载失败显示人员占位图标。

积分账本不依赖飞书多维表格或 AnyCross。MySQL 8 结构仅由 `database/schema.sql` 维护，变更按日期追加在末尾，管理员手动执行；本地启动和 Docker Compose 均不修改数据库结构。事务和通知网络调用分离；通知发送重试不能更改月度余额。

撤回按每笔记分判断：全部通知成功撤回才作废积分，部分撤回、未发送、失败或待核实仍保留积分。作废审计、余额重算及最后一条撤回成功状态在同一事务内保存，与记账共用写锁；唯一流水主键防止重复作废。重算该月有效流水时按原余额版本排序，避免同秒时间戳打乱手动覆盖的先后顺序。月度余额版本递增使旧预览失效，即使后续覆盖导致总分不变也需要重新预览。原流水、卡片和消息 ID 均保留；worker 补处理历史全部撤回的记分。
